# تیشه — تحویل قالب مشکی و طلایی Craft UI

**تاریخ:** ۱۴ آبان ۱۴۰۵ / 2026-11-05  
**مبنای کد:** مخزن `amirbojary1-sys/tisheh`، کامیت `3712167e714e411556a942b6c9bbf3336502d012`  
**شاخه محلی:** `development/next-version` — تغییری به GitHub پوش نشده است.

این مرحله، بازطراحی وب‌اپ موجود بر اساس دو تصویر ارسالی است؛ بازنویسی از صفر، گالری عکس یا افزودن قابلیت‌های ساختگی نیست. نسخه پیشین در مسیر جداگانه نگهداری شده و دیتابیس آن استفاده نشده است.

## مشاهده و استفاده

پیش‌نمایش زنده با عنوان **«تیشه — وب‌اپ مشکی و طلایی»** روی پورت **۸۰۰۱** اجرا می‌شود. این یک برنامه Laravel متصل به دیتابیس توسعه است، نه تصویر سایت. از لینک Live Preview همین گفتگو استفاده کنید.

برای تجربه پنل، می‌توانید از «عضویت» حساب جدید کارگر/استادکار، کارفرما یا فروشنده بسازید. در پیش‌نمایش محلی، ورود آزمایشی چهاررقمی نیز برای این حساب‌های نمونه فعال است:

| نقش نمونه | شماره آزمایشی |
|---|---|
| کارگر / استادکار | `09000000003` |
| کارفرما | `09000000002` |
| فروشنده | `09000000004` |

در صفحه ورود، «کد چهاررقمی آزمایشی» را انتخاب کنید؛ کد تولیدشده فقط روی صفحه بعد نمایش داده می‌شود. پیامکی ارسال نمی‌شود و شماره تأیید واقعی نمی‌شود. حساب مدیر با این روش وارد نمی‌شود. کلید برنامه، رمزهای حساب‌ها و دیتابیس خصوصی در بسته سورس نیستند. شماره‌های بالا داده نمونه‌اند، نه شماره کاربران واقعی.

| ورود | کارت ورود یکپارچه، تفکیک رمز/کد آزمایشی، نمایش و پنهان‌کردن رمز، حفظ اعتبارسنجی و CSRF |

| بازار مصالح | کارت و تصاویر، فیلتر، مقایسه، فرم فروشنده و نمایش جزئیات با سبک مشترک؛ مسیر عکس‌های بارگذاری‌شده فروشندگان حفظ شده است |
| حساب و ارتباط | پنل‌های نقش‌های موجود، پروفایل، پیام‌ها، اعلان‌ها و پشتیبانی از همان پوسته مشترک استفاده می‌کنند |
| خرید | سبد، سفارش، تاریخچه و صفحات پرداخت آزمایشی از همان سیستم رنگ، فاصله، دکمه و کارت استفاده می‌کنند؛ منطق رزرو/تقسیم سفارش و مبالغ تغییر نکرده است |
| مدیریت و صفحات دیگر | پنل مستقل مدیر، جداول، بررسی آگهی، دسته‌بندی، تنظیمات، محتوا، خطاها و صفحات راهنما با پوسته مشترک هماهنگ شده‌اند |

در بعضی بخش‌ها تغییر اصلی از طریق CSS و layout مشترک اعمال شده است، نه بازنویسی تک‌تک viewها. لینک‌ها، فرم‌ها، نام فیلدها، مجوزها و مسیرهای موجود حفظ شده‌اند. ثبت درخواست و عضویت بدون جاوااسکریپت نیز به‌صورت فرم کامل قابل استفاده‌اند؛ جاوااسکریپت فقط نمایش مرحله‌ای را اضافه می‌کند.

### تفاوت‌های آگاهانه با تصاویر مرجع

- فاصله نزدیک‌ترین نیرو، ستاره، نظر، نشان تأیید و سابقه کاری خیالی نمایش داده نمی‌شود.
- فهرست عمومی نیروی نزدیک و پروفایل عمومی نیروی کار در این نسخه مخزن وجود نداشت؛ مسیر یا اطلاعات نمایشی جایگزین آن ساخته نشده است.
- ورود Google، نقشه زنده، هزینه ثبت درخواست، احراز مالکیت موبایل، دریافت کد ملی یا تاریخ تولد بدون پشتوانه فعلی اضافه نشده‌اند.
- نقش فروشنده فعلی حذف نشده است؛ زیرنوع‌ها و مدل چندنقشی در این مرحله بازطراحی نشده‌اند.
- فرم درخواست نیرو از آدرس متنی واقعی سامانه استفاده می‌کند و موقعیت تأییدشده روی نقشه ادعا نمی‌کند.
- نسخه دسکتاپ، تطبیق واکنش‌گرای همین زبان بصری است، نه قاب بزرگ‌شده یک تلفن.

## ساختار فنی و فایل‌ها

- `public/css/craft.css`: سیستم رنگ، کنترل‌ها، پوسته، خانه، auth، کارت‌ها، پنل‌ها و واکنش‌گرایی. پس از CSSهای موجود بارگذاری می‌شود تا ساختار سالم قبلی حذف نشود.
- `public/js/craft.js`: نمایش رمز، مراحل فرم‌ها، بازگشت به خطا، فیلتر موبایل و بستن منو با Escape.
- `resources/views/layouts/{app,admin}.blade.php`: اتصال دارایی‌های محلی و پوسته مشترک.
- `resources/views/home.blade.php`، `auth/*`، `jobs/*`: خانه و جریان‌های اصلی بازطراحی‌شده.
- `resources/views/components/{logo,icon,job-card,product-card,product-photo,skyline}.blade.php`: اجزای قابل استفاده مجدد.
- `resources/views/products/{index,show,form}.blade.php`: فیلتر و نمایش تصاویر در فهرست، جزئیات و مدیریت تصاویر.
- `app/Http/Controllers/JobController.php`: تنها تغییر کاربردی سمت سرور، خواندن درخواست قبلی **همان کاربر** برای نمایش وضعیت در جزئیات است؛ منطق ثبت، مجوز و تراکنش تغییری نکرده است.
- `tests/Feature/CraftDesignTest.php`: هشت تست رگرسیون جدید برای پوسته، فرم‌ها، مجوز، تصاویر و حریم خصوصی وضعیت درخواست.
- `tests/browser/*`: اسکریپت‌های مرورگر قابل تکرار؛ اجرای workflow، داده آزمایشی ایجاد می‌کند.
- `docs/qa/craft-*.txt`: خروجی تست‌های همین مرحله؛ گزارش‌های قدیمی مخزن نتیجه این مرحله نیستند.

**دیتابیس:** هیچ migration یا جدول جدیدی در این مرحله اضافه نشده، هیچ schema یا تاریخچه مالی بازنویسی نشده و دیتابیس قدیمی ادغام نشده است. پیش‌نمایش از SQLite جداگانه استفاده می‌کند. تنظیمات استقرار MySQL و قالب cPanel قبلی حفظ شده‌اند.

## تصاویر و فونت

- `public/images/craft-hero.webp`: تصویر نمایشی تولیدشده با هوش مصنوعی، نه عکس کارفرما/کارگر تأییدشده یا یک پروژه واقعی؛ نسخه WebP حدود ۱۳۲ کیلوبایت است.
- `public/images/materials/{cement,steel,brick,sand}.webp`: بازاستفاده از دارایی‌های تصویری نمایشی قبلی پروژه برای چهار نوع محصول نمونه.
- فقط چهار مسیر دقیق `samples/cement.svg`، `samples/steel.svg`، `samples/brick.svg` و `samples/sand.svg` به این تصاویر نمایشی نگاشت می‌شوند. متن و alt آنها نمایشی‌بودن را روشن می‌کند. مسیر تصاویر واقعی فروشندگان عوض نمی‌شود.
- تصاویر آگهی کار تزئینی‌اند و برچسب «نمایشی» دارند؛ عکس پروژه واقعی ادعا نمی‌شود.
- `public/fonts/Vazirmatn.woff2` و مجوز `OFL.txt` موجود حفظ شده‌اند؛ وابستگی به CDN فونت یا کتابخانه بیرونی در مرورگر اضافه نشده است.

## راه‌اندازی از سورس

بسته همراه، **سورس** است؛ `vendor`، `.env`، رمزها، دیتابیس، نشست‌ها و لاگ‌های خصوصی را ندارد. نسخه آماده بارگذاری مستقیم cPanel یا APK نیست.

۱. PHP مطابق `composer.json` همراه افزونه‌های موردنیاز پروژه، Composer و MySQL را آماده کنید. برای تولید از `deploy/cpanel.env.example` طبق راهنمای استقرار موجود استفاده کنید و `.env` را خصوصی نگه دارید.

۲. در نصب تازه، تنظیمات صحیح دیتابیس خالی را وارد کنید؛ کلید جدید برنامه را ایجاد کنید. روی سایت موجود کلید فعلی را بی‌دلیل عوض نکنید:

```bash
composer install --no-interaction
cp deploy/cpanel.env.example .env
# ویرایش تنظیمات اتصال، دامنه و محیط پیش از ادامه
php artisan key:generate --force
php artisan migrate --seed --force
php artisan storage:link
php artisan tisheh:admin
php artisan view:cache
```

برای به‌روزرسانی سایت موجود، پشتیبان بگیرید و `docs/DEPLOYMENT.fa.md` و `docs/PROJECT-GUIDE.fa.md` را بخوانید؛ دیتابیس این پیش‌نمایش را جایگزین اطلاعات واقعی نکنید. سرور توسعه را روی هاست عمومی تولید اجرا نکنید.

۳. فقط در محیط محلی و دیتابیس خالی/جداگانه، برای دیدن داده نمونه، `APP_ENV=local` قرار دهید و `php artisan db:seed --class=DemoSeeder` را اجرا کنید. خروجی دارای رمزهای تصادفی خصوصی است؛ آن را عمومی یا commit نکنید.

در پیش‌نمایش این گفتگو `CSP_FRAME_ANCESTORS=*` و proxy باز فقط در **فایل محیط خصوصی محلی** برای نمایش داخل iframe تنظیم شده‌اند. روی تولید، محدودیت frame و proxy را مطابق میزبان خود نگه دارید. `script-src` و `style-src` همچنان `self` هستند؛ `unsafe-inline` اضافه نشده است. تأیید حذف درخواست از handler درون‌خطی ناسازگار با CSP به `data-confirm` مشترک منتقل شده است.

### تکرار تست‌ها

```bash
php artisan test
vendor/bin/pint --test app/Http/Controllers/JobController.php tests/Feature/CraftDesignTest.php
php artisan view:cache
```

برای Chromium، در `tests/browser` وابستگی‌ها را نصب و مرورگر را دریافت کنید. اسکریپت workflow عمداً رکورد ایجاد، منتشر و سفارش رزرو می‌کند؛ **هرگز روی دیتابیس واقعی اجرا نکنید.**

```bash
cd tests/browser
npm install
npx playwright install chromium
BASE_URL=http://127.0.0.1:8001 npm run test:visual

# مسیر فایل خصوصی خروجی DemoSeeder؛ حاوی رمز است و نباید در Git قرار گیرد.
BASE_URL=http://127.0.0.1:8001 \
ALLOW_DEMO_WRITES=TISHEH-DEMO-ONLY \
DEMO_CREDENTIALS_FILE=/absolute/private/demo-credentials.txt \
npm run test:e2e
```

برای تست OTP فقط در محیط محلی، `TISHEH_DEMO_OTP_ENABLED=true` و allowlist `DEMO_OTP_MOBILES=09000000002,09000000003,09000000004` لازم است؛ سپس با همان تأیید `ALLOW_DEMO_WRITES` اسکریپت `test:otp` اجرا می‌شود. در تولید، دمو حتی با پرچم محیط نیز باید طبق محافظ موجود مسدود بماند. پرداخت واقعی، SMS، کیف پول و احراز هویت واقعی همچنان به اتصال و بررسی مستقل نیاز دارند.

## باقی‌مانده‌ها

بازبینی نهایی شما برای نزدیکی بصری به مرجع، آزمایش دستگاه و مرورگر واقعی، استقرار مقصد و بررسی MySQL/MariaDB همین نسخه باقی است. قابلیت‌های جدیدی که داده/زیرساخت ندارند—نیروی نزدیک، امتیاز معتبر، چندنقشی توسعه‌یافته، نقشه، Google login، بانک و SMS واقعی—بخشی از ادعای تکمیل این مرحله نیستند. هیچ کلید امضای Android یا APK جدیدی ایجاد نشده است.
