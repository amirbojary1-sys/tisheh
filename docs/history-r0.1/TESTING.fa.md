# راهنمای آزمون r0.1

## تست خودکار backend

```bash
composer install
php artisan test
vendor/bin/pint --test
composer audit
php artisan view:cache
```

`phpunit.xml` به‌صورت پیش‌فرض SQLite در حافظه دارد. دیتابیس پیش‌نمایش از آن جداست. برای تست درایور mysql، متغیرهای محیطی DB را به دیتابیس تست مستقل بدهید؛ `RefreshDatabase` ممکن است جداول آن را حذف کند. APP_KEY معتبر تست/محلی باید موجود باشد.

در تحویل: ۳۹ تست با ۱۲۶ assertion روی SQLite و MariaDB 11.8.6 با درایور mysql پاس شدند. **MySQL 8 مستقل در این محیط اجرا نشده است.** گزارش‌های raw در پوشه docs هستند.

پوشش:

- ثبت‌نام نقش مجاز، نیازمندی‌های نقش فروشنده و کارگر، نرمال‌سازی شماره فارسی، موبایل تکراری و رمز ضعیف.
- هش رمز، حفظ نام فرم و عدم حفظ رمز، ورود/خروج، رد رمز اشتباه و حساب مسدود و محدودیت ورود.
- اجبار login، محدودیت نقش، جلوگیری از انتشار خودسرانه و کنترل مالکیت و آدرس خصوصی.
- ایجاد/ویرایش draft و pending، اعلام آمادگی یکتا، بررسی متقاضی فقط توسط مالک.
- ثبت محصول، محدودیت انتشار، جلوگیری از آپلود SVG و re-encode تصویر معتبر به WebP.
- جلوگیری از مقایسه محصول منتشرنشده، unknown حمل و عدم گردکردن یک ریال در نمایش.
- فیلترهای دیتابیس، escape خروجی XSS، audit مدیریت و منع حذف/تغییر مدل audit.
- منع تغییر نقش/تأیید موبایل از فرم profile، رندر پنل همه نقش‌ها، رد payload آرایه‌ای موبایل و موجودی صفر.
- غیرفعال‌بودن مالی و نبود مسیر wallet.

## آزمون مرورگر قابل بازتولید

فقط روی محیط disposable دارای داده نمونه اجرا کنید. اسکریپت حساب و آگهی واقعی ایجاد می‌کند؛ production نباید هدف آن باشد. در این نسخه اسکریپت **پاک‌سازی خودکار داده ایجادشده ندارد** تا داده واقعی اشتباهی پاک نشود. برای تکرار، از دیتابیس توسعه تازه یا بازنشانی تأییدشده محیط تست استفاده کنید.

۱. با `APP_ENV=local` Migration و DatabaseSeeder را اجرا کنید.
۲. در دیتابیس تازه، خروجی اولین اجرای DemoSeeder را در فایل خصوصی خارج از public ذخیره کنید. فایل شامل رمز تصادفی نمونه است و نباید commit شود:

```bash
umask 077
php artisan db:seed --class=DemoSeeder > /secure/local-demo-credentials.txt
```

۳. سایت را اجرا کنید و وابستگی QA نصب شود:

```bash
npm ci
npx playwright install --with-deps chromium
# در shell دیگر
php artisan serve --host=0.0.0.0 --port=8000
```

۴. آزمون را با رضایت صریح به ایجاد داده اجرا کنید:

```bash
TISHEH_E2E_ALLOW_WRITE=1 \
TISHEH_CREDENTIALS=/secure/local-demo-credentials.txt \
TISHEH_BASE_URL=http://127.0.0.1:8000 \
npm run test:browser
```

گزارش پیش‌فرض در `storage/logs/browser-results.txt` ذخیره می‌شود؛ مسیر را می‌توان با `TISHEH_BROWSER_REPORT` تغییر داد. فایل credential را پس از استفاده طبق سیاست محیط تست نگهداری/حذف کنید. اگر DemoSeeder پیش‌تر اجرا شده باشد، اجرای دوباره رمزهای قبلی را چاپ نمی‌کند؛ از حساب‌های همان محیط و credential اولیه استفاده کنید.

## سناریوی دستی مرحله‌ای

### ۱. حساب و نقش

کارگر بسازید، فیلد تخصص خالی را امتحان کنید، سپس کامل و وارد شوید. تلاش برای `/jobs/create` و `/admin` باید 403 شود. خروج را از حساب انجام دهید. فروشنده بدون نام و آدرس فروشگاه نباید ثبت‌نام شود. نقش admin از payload فرم نباید پذیرفته شود.

### ۲. کاریابی

کارفرما درخواست با توضیح کوتاه/تاریخ گذشته بفرستد: خطاهای فارسی و حفظ اطلاعات بررسی شود. فرم معتبر را به pending بفرستد. در مرورگر مهمان نباید آگهی pending دیده شود. مدیر آگهی را تأیید کند. کارگر وارد شود، پیدا کند و اعلام آمادگی کند. تکرار آن رد شود. کارفرما نتیجه را بپذیرد و کارگر در پنل ببیند.

### ۳. مصالح

فروشنده نام، دسته، برند، مشخصات، قیمت ریالی، واحد و موجودی وارد کند؛ تصویر معتبر و سپس SVG نامعتبر آزموده شود. مدیر تأیید کند. در بازار، نام/برند/شهر را فیلتر و دو پیشنهاد را مقایسه کنید. حمل خالی نباید به‌صورت رایگان نشان داده شود. قیمت و موجودی را ویرایش کنید؛ انتشار مجدد باید بررسی بخواهد. مالک بتواند غیرفعال کند، غیرمالک نتواند ویرایش کند.

### ۴. امنیت و حریم خصوصی

مهمان نباید موبایل آگهی را ببیند. آدرس خصوصی پروژه نباید در HTML عمومی باشد. ارسال بدون CSRF باید 419 بدهد. ورودی `<script>` در شرح به شکل متن نمایش داده شود. مدیر دیگر از UI مسدود نشود. لاگ عمل مدیریتی در پنل read-only دیده شود.

### ۵. موبایل

عرض‌های ۳۹۰، ۷۶۸ و ۱۴۴۰، focus با صفحه‌کلید، خطای فرم، ورود/خروج و منوی پایین را بررسی کنید. فعلاً منوی پیام‌ها وجود ندارد چون ماژول پیام‌رسان هنوز پیاده‌سازی نشده است؛ دکمه نمایشی بدون عملکرد قرار داده نشده.

## حدود اعتبار گزارش

موفقیت تست، تضمین بی‌نقصی یا آمادگی تجاری نیست. ممیزی مستقل امنیت، تست بار، MySQL 8 مستقل، رقابت چند اتصال همزمان، دستگاه Android واقعی، خدمات بیرونی و تست مالی بعد از پیاده‌سازی باقی هستند.
