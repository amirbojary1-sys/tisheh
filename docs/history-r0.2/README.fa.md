# تیشه | TISHEH — نسخه توسعه r0.2

**این نسخه جایگزین r0.1 است.** تاریخ: ۲۴ اکتبر ۲۰۲۶.

وب واقعی Laravel 12 با Blade، دیتابیس متصل و قالب بازطراحی‌شده بر اساس تصاویر مرجع کارفرما؛ مشکی و طلایی، کارت‌های تیره، دکمه‌های گرد، ناوبری اپلیکیشنی و پنل مستقل ادمین. هیچ صفحه‌ای جایگزین backend نشده است.

> محیط توسعه است. آگهی‌ها، هویت‌ها، قیمت‌ها، موجودی‌ها و سفارش‌های اولیه/آزمون، داده آزمایشی‌اند. ثبت سفارش، پیام و اعلان واقعاً در دیتابیس انجام می‌شود؛ اما **پرداخت بانکی، دریافت وجه، موجودی کیف پول و تسویه فعال نیستند**. در سایت فرم اطلاعات کارت یا رسید پرداخت ساختگی وجود ندارد.

## ۱. قابلیت‌های جدید این تحویل

### پنل مستقل ادمین

| مسیر | عملکرد |
|---|---|
| `/admin` | داشبورد تعداد واقعی کاربران، درخواست‌ها، مصالح و سفارش‌ها؛ نمودار واقعی ثبت فعالیت هفت روز و رویدادهای اخیر |
| `/admin/users` | جستجوی نام/موبایل، فیلتر نقش و وضعیت، صفحه جزئیات |
| `/admin/users/{id}` | ویرایش نام/شهر کاربر غیرمدیر، فعال/مسدودسازی با دلیل و لاگ؛ ابطال نشست حساب مسدودشده |
| `/admin/listings/job` | همه درخواست‌های کار، جستجو/فیلتر وضعیت، تأیید/رد و توقف انتشار با دلیل |
| `/admin/listings/product` | بررسی مصالح و ارتباط با فروشنده؛ اعلان نتیجه به صاحب آگهی |
| `/admin/orders` | نظارت و فیلتر سفارش‌های مستقیم؛ مشاهده جزئیات بدون دستکاری وضعیت پرداخت |
| `/admin/categories` | ایجاد و ویرایش تخصص/دسته مصالح؛ حذف فقط دسته بدون آگهی |
| `/admin/reports` | پیگیری گزارش و شکایت، رسیدگی، پاسخ به کاربر و ثبت مسئول پاسخ |
| `/admin/pages` | ساخت/ویرایش و انتشار صفحات محتوایی و راهنما با خروجی امن متنی |
| `/admin/settings` | شماره/ایمیل پشتیبانی، اطلاعیه و ذخیره مبالغ پیشنهادی آگهی/اشتراک؛ **دریافت هزینه فعال نمی‌شود** |
| `/admin/roles` | نمایش ماتریس نقش‌ها/مجوزها و تعداد اعضا؛ عمداً فقط‌خواندنی |
| `/admin/finance` | نمایش وضعیت عدم اتصال مالی و ارزش اسمی سفارش‌ها؛ نه درآمد یا وجه وصول‌شده |
| `/admin/audit` | جستجو بر اساس رویداد، عامل و تاریخ؛ مشاهده متادیتا؛ خروجی CSV تا ۵۰۰۰ ردیف |

مدیر نمی‌تواند از فرم کاربر نقش admin جعل کند، موبایل را تأیید کند یا حساب مدیر را مسدود کند. ساخت مدیر همچنان از دستور امن `tisheh:admin` انجام می‌شود. تغییر لاگ و رکورد مالی در رابط وجود ندارد؛ AuditLog در سطح مدل append-only است، نه جایگزین لاگ مستقل زیرساخت.

### پیام و اعلان

- `/messages`: گفتگوی خصوصی مرتبط با آگهی منتشرشده؛ شروع از دکمه پیام در صفحه کار/محصول.
- تنها آغازکننده و صاحب آگهی می‌توانند گفتگو را بخوانند یا پیام بفرستند؛ حتی مدیر دسترسی عمومی به محتوای گفتگوی دیگران ندارد.
- پیام‌ها متن امن هستند، حداکثر ۴۰۰۰ نویسه؛ وضعیت آنلاین/تحویل یا رمزنگاری سرتاسری ادعا نمی‌شود.
- `/notifications`: اعلان واقعی دیتابیسیِ آگهی، اعلام آمادگی، نتیجه بررسی، پیام، سفارش و پاسخ پشتیبانی؛ خواندن تکی و همه.
- SMS، Push و اتصال WebSocket/بلادرنگ پیاده‌سازی نشده‌اند. برای مشاهده پیام جدید، صفحه دوباره بارگذاری شود.

### سفارش مستقیم واقعی

- ثبت از صفحه محصول با مقدار، آدرس تحویل خصوصی و یادداشت.
- کنترل حداقل سفارش/موجودی، محاسبه قیمت در سرور و snapshot نام، برند، واحد و قیمت.
- رزرو موجودی در تراکنش دیتابیس و قفل سطر؛ کلید idempotency مختص خریدار برای جلوگیری از ثبت تکراری همان درخواست.
- `/orders`: پیگیری خریدار/فروشنده و تاریخچه وضعیت.
- `awaiting_seller → confirmed → ready_to_ship → shipped → delivered`؛ تحویل فقط توسط خریدار. لغو طبق قواعد محدود و برگشت موجودی فقط یک بار.
- اگر حمل نامشخص باشد total نیز نامشخص می‌ماند؛ فروشنده برای تأیید، مبلغ حمل را تعیین کند. خریدار پیش از هر پرداخت مستقیم باید مبلغ را بررسی و توافق کند.
- پرداخت همیشه `unverified_external` است؛ تحویل کالا پرداخت را تأیید نمی‌کند. شماره پیگیری سفارش UUID است، نه شماره تراکنش بانکی.
- رزرو خودکار منقضی نمی‌شود؛ خریدار/فروشنده باید سفارش رهاشده را در حالت مجاز لغو کنند. timeout و reconciliation رزرو برای نسخه بعد است.
- مدیر ناظر سفارش است، نه طرف مجاز برای انتقال وضعیت تجاری یا پولی.

### پشتیبانی و پروفایل

- `/reports`: گزارش آگهی یا درخواست پشتیبانی، پیگیری خصوصی و مشاهده پاسخ ادمین.
- ویرایش تخصص کارگر و نام/آدرس فروشگاه از پنل حساب اضافه شد.
- آگهی‌های صاحب حساب مسدودشده از جستجوی عمومی و دسترسی عمومی حذف می‌شوند؛ داده برای بررسی مدیر باقی می‌ماند.

## ۲. امکانات باقی‌مانده از نسخه قبل

ثبت‌نام نقش کارگر/استادکار، کارفرما/پیمانکار، فروشنده؛ ورود با موبایل و رمز، کنترل نقش/مالکیت، ثبت درخواست نیرو و اعلام آمادگی و پذیرش متقاضی؛ آگهی مصالح با تصویر بازرمزگذاری‌شده WebP؛ جستجو، فیلتر شهر/دسته/برند، مرتب‌سازی و مقایسه ۲ تا ۴ محصول؛ تماس پس از ورود؛ جستجوی آدرس روی نقشه خارجی.

موبایل هنوز احراز نشده است. آدرس پروژه عمومی نیست، آدرس فروشگاه عمومی است؛ آدرس تحویل فقط برای طرفین سفارش و مدیر مجاز قابل مشاهده است.

## ۳. فناوری و طراحی

PHP 8.4.27 در محیط تحویل؛ Laravel 12.70.1؛ Eloquent و Migration؛ Blade، CSS و JavaScript. درایور واقعی `mysql` روی **MariaDB 11.8.6**؛ تست مستقل MySQL 8 در این محیط انجام نشده است. `compose.mysql.yaml` اختیاری برای MySQL 8.4 است و اجرای آن در این محیط تأیید نشده است.

- `public/css/app.css`: سبک‌های مشترک پایه.
- `public/css/reference.css`: توکن‌های نهایی برند و بازطراحی مرجع؛ رنگ‌ها در ابتدای این فایل متمرکزند.
- `public/js/app.js`: جستجو، نقش ثبت‌نام، انتخاب مقایسه و تأیید حذف دسته.
- `resources/views/layouts/app.blade.php`: وب اپ فارسی با منوی پایین پنج‌تایی.
- `resources/views/layouts/admin.blade.php`: پوسته مستقل ادمین با سایدبار دسکتاپ و ناوبری افقی موبایل.
- فونت Vazirmatn محلی با OFL؛ بدون CDN. تصویر سربرگ تولیدشده با هوش مصنوعی و تصاویر مصالح شماتیک‌اند. تصویر تزئینی روی کارت کار، عکس واقعی همان پروژه نیست.
- اعداد و تاریخ نمایشی فارسی؛ تاریخ ورودی فرم‌های native مرورگر با برچسب میلادی است.

## ۴. نصب تازه

پیش‌نیاز: PHP 8.2+، Composer 2، MySQL/MariaDB سازگار، PDO MySQL، mbstring، XML/DOM، openssl، fileinfo، tokenizer، ctype و GD با WebP. برای تست حافظه‌ای افزونه pdo_sqlite لازم است.

```bash
cd tisheh
composer install
cp .env.example .env
php artisan key:generate
```

دیتابیس UTF-8 و کاربر اختصاصی بسازید و متغیرهای `DB_CONNECTION=mysql`، `DB_HOST`، `DB_DATABASE`، `DB_USERNAME` و `DB_PASSWORD` را در `.env` تنظیم کنید. رمز واقعی در Git قرار نگیرد.

```bash
php artisan migrate --seed
php artisan storage:link
php artisan tisheh:admin
php artisan serve --host=0.0.0.0 --port=8000
```

`storage:link` برای نمایش تصاویر ضروری است. npm برای اجرای وب لازم نیست؛ تنها آزمون مرورگر به آن نیاز دارد. DatabaseSeeder نقش/دسته/کشور و صفحات help/about را می‌سازد، نه حساب نمونه یا پول نمایشی.

### ارتقا از r0.1

ابتدا backup معتبر DB و فایل‌ها بگیرید. APP_KEY اصلی و `.env` خود را حفظ کنید؛ کلید جدید نسازید.

```bash
composer install
php artisan migrate --force
php artisan db:seed --class=ContentSeeder --force
php artisan storage:link
php artisan optimize:clear
```

Migrationهای جدید جدول‌های گفتگو، پیام، اعلان، گزارش، محتوا، سفارش، اقلام و رویداد سفارش و کلید یکتای idempotency خریدار را ایجاد می‌کنند. Migrationهای قبلی جایگزین یا پاک نشده‌اند.

### مدیر و داده نمونه

```bash
php artisan tisheh:admin
# بازیابی اضطراری توسط اپراتور پس از احراز مالکیت خارج از سامانه
php artisan tisheh:reset-password
# فقط توسعه؛ رمزها در اولین ایجاد حساب تصادفی چاپ می‌شوند
php artisan db:seed --class=DemoSeeder
```

هیچ رمز پیش‌فرض مدیر در سورس نیست. DemoSeeder فقط در local/testing اجرا می‌شود و در production ممنوع است. فایل حساب‌های پیش‌نمایش این گفتگو جدا از سورس است.

## ۵. تست و نتیجه

```bash
php artisan test
php vendor/bin/pint --test
composer audit
```

**۷۲ تست با ۲۶۵ assertion موفق** روی SQLite و مجدداً MariaDB با درایور mysql. علاوه بر ۳۹ تست قبلی، پوشش مدیریت، دسته، محتوا، تنظیمات خالی، محدودیت نقش، پیام خصوصی، گزارش، اعلان، snapshot سفارش، idempotency، منع overselling، برگشت موجودی، گردش نقش‌محور و مبلغ حمل اضافه شده است.

آزمون مرورگر Chromium: هر ۱۳ مسیر ادمین، صفحات عمومی و پنل‌ها؛ نبود بیرون‌زدگی افقی در عرض ۳۹۰/۷۶۸/۱۴۴۰؛ نبود تصویر شکسته؛ گفتگوی دوطرفه؛ رد خواندن توسط شخص ثالث؛ سفارش تا تحویل با پرداخت تأییدنشده؛ پاسخ ادمین به گزارش و اعلان؛ بدون خطای JavaScript در گردش آزموده‌شده.

`tests/Browser/e2e.cjs` فقط روی محیط disposable دارای DemoSeeder و رضایت `TISHEH_E2E_ALLOW_WRITE=1` اجرا شود؛ فایل رمز از `TISHEH_CREDENTIALS` و URL از `TISHEH_BASE_URL` دریافت می‌شود. این تست عمداً داده آزمون و سفارش ایجاد می‌کند و پاک‌سازی خودکار ندارد. جزئیات در docs/TESTING.fa.md است.

موفقیت تست، تضمین آمادگی تولید نیست. تست چند اتصال واقعاً همزمان، بار/نفوذ، MySQL 8 مستقل، Android و خدمات مالی بیرونی انجام نشده‌اند.

## ۶. بخش‌های هنوز تحویل‌نشده

- OTP/بازیابی خودکار SMS و احراز هویت حرفه‌ای؛ نیازمند سرویس معتبر منتخب کارفرما.
- درگاه پرداخت، کیف پول، دستمزد، برداشت، دفترکل مالی، رسید بانکی، تسویه و بازپرداخت؛ نیازمند بررسی حقوقی و provider مجاز.
- اعمال واقعی هزینه انتشار/اشتراک، تبلیغات و گزارش درآمد وصول‌شده؛ تنظیم مبلغ به‌تنهایی این قابلیت‌ها را فعال نمی‌کند.
- ویرایش نقش/مجوز و ساخت مدیر از UI؛ ماتریس فعلی فقط‌خواندنی است.
- موقعیت جغرافیایی معتبر/فاصله، دایرکتوری نیروها و امتیاز/نظر مبتنی بر سابقه معتبر، نقشه تعاملی و نمونه‌کار عمومی.
- تصاویر پروژه، مدیریت حذف تصاویر قبلی محصول، فیلتر بازه تاریخ و حداکثر دستمزد، lifecycle کامل in_review و بازگشایی درخواست.
- پیام‌رسان بلادرنگ، فایل پیام، Push، MFA مدیر، سیاست نهایی حذف/نگهداری داده و ممیزی مستقل.
- نسخه عربی/عراق و ضوابط حقوقی و پرداخت آن کشور.
- Android WebView، APK آزمایشی و APK release امضاشده. دامنه HTTPS نهایی و کلید امضای کارفرما هنوز لازم‌اند.
